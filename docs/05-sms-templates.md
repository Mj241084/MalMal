# ۰۵ — قالب‌های پیامک (sms.ir) — نسخه ۰.۵

این سند دو کار دارد: (۱) متن دقیق قالب‌هایی که کاربر (صاحب پروژه) در پنل sms.ir ثبت می‌کند، (۲) قرارداد پارامترها بین قالب‌ها و کد، تا Claude Code دقیقاً همان نام‌ها را بفرستد.

بررسی‌شده با مستندات رسمی (`docs/vendors/smsir/smsir-api.md`): در متد «ارسال سریع / Verify» هر پارامتر به شکل `{ "name": "NAME", "value": "..." }` (بدون `#` در نام کلید) فرستاده می‌شود و حداکثر طول مجاز برای هر `value` دقیقاً **۲۵ کاراکتر** است (کد وضعیت `114` در صورت تجاوز). تنها موردی که هنگام ثبت در پنل باید دستی بررسی شود پذیرش `##CODE#` در خط WebOTP است.

---

## ۱. راهنمای ثبت (برای کاربر)

1. در پنل sms.ir بخش قالب‌های «ارسال سریع/وریفای» (نام منو ممکن است فرق کند) برای هر ردیف جدول زیر یک قالب بساز.
2. متن را **عیناً** کپی کن. جاهایی که `#NAME#` نوشته شده، پارامتر است. نام پارامتر را با همین حروف بزرگ انگلیسی بساز.
3. بعد از تایید sms.ir، شناسه‌ی قالب را در `.env` بگذار (نام متغیر در جدول).
4. شناسه‌ها را در گفتگو نفرست. فقط در `.env`.
5. حداقل برای شروع کار و انتشار لازم است: `otp`، `order_paid`، `order_shipped`. بقیه اختیاری‌اند و می‌توان بعداً ثبت کرد. (چون فعلاً همه‌ی ارسال‌ها با تیپاکس و با کد رهگیری است، `order_shipped_courier` لازم نیست.)

**نکته‌ی دامنه (کار را متوقف نمی‌کند):** دامنه هنوز مشخص نیست. فعلاً قالب `otp` را به‌صورت **نسخه‌ی جایگزین (بدون خط آخر)** ثبت کن و شناسه‌اش را در `.env` بگذار. وقتی دامنه مشخص شد، نسخه‌ی اصلی (با خط `@دامنه ##CODE#`) را ثبت کن و فقط `SMSIR_TEMPLATE_ID_OTP` را عوض کن؛ به کد دست نمی‌زنی. بدون آن خط فقط پر شدن خودکار کد در مرورگر کار نمی‌کند و کاربر کد را دستی (یا از پیشنهاد کیبورد) وارد می‌کند.

## ۳. متن قالب‌ها

### ۳.۱ `otp`: کد ورود

نسخه‌ی اصلی (با خط آخر برای پر شدن خودکار کد؛ `YOUR-DOMAIN` را با دامنه‌ی سایت عوض کن، مثلاً `example.ir`):

```
مل‌مل
کد تایید شما: #CODE#
این کد را به هیچ‌کس ندهید.

@YOUR-DOMAIN ##CODE#
```

- خط آخر باید **آخرین خط پیامک** و به همین شکل باشد: `@دامنه` ، فاصله ، `#` ، کد. بنابراین `##CODE#` یعنی یک `#` واقعی به‌علاوه‌ی پارامتر `#CODE#`.
- `[VERIFY]` اگر پنل پارامتر تکراری یا `#` پشت‌سرهم را نپذیرفت، از نسخه‌ی جایگزین استفاده کن.

نسخه‌ی جایگزین (بدون خط آخر؛ تکمیل خودکار فقط از پیشنهاد کیبورد گوشی کار می‌کند):

```
مل‌مل
کد تایید شما: #CODE#
این کد را به هیچ‌کس ندهید.
```

پارامترها: `CODE` (۴ رقم، ارقام انگلیسی).

### ۳.۲ `order_paid`: ثبت و پرداخت سفارش

```
مل‌مل
سفارش #ORDER# به مبلغ #AMOUNT# تومان ثبت و پرداخت شد.
وضعیت سفارش را از بخش «سفارش‌های من» ببینید.
```

پارامترها: `ORDER` (مثل `ML-48201937`)، `AMOUNT` (با جداکننده‌ی هزارگان لاتین، مثل `1,250,000`).

### ۳.۳ `order_shipped`: ارسال با کد رهگیری

```
مل‌مل
سفارش #ORDER# ارسال شد.
روش ارسال: #CARRIER#
کد رهگیری: #TRACKING#
```

پارامترها: `ORDER`، `CARRIER` (عنوان روش ارسال؛ فعلاً «تیپاکس»)، `TRACKING` (اجباری؛ ادمین موقع تغییر وضعیت به ارسال‌شده باید کد را وارد کند).

### ۳.۴ `order_shipped_courier`: ارسال با پیک فروشگاه

```
مل‌مل
سفارش #ORDER# به پیک تحویل داده شد و به‌زودی به دست شما می‌رسد.
```

پارامترها: `ORDER`. کد باید بر اساس نوع روش ارسال (فیلد «با کد رهگیری؟» در `ShippingMethod`) یکی از دو قالب ارسال را انتخاب کند.

### ۳.۵ `order_delivered` (اختیاری): تحویل سفارش

```
مل‌مل
سفارش #ORDER# تحویل داده شد. از خرید شما سپاسگزاریم.
نظر شما درباره‌ی کالا برای ما ارزشمند است.
```

پارامترها: `ORDER`.

### ۳.۶ `order_cancelled` (اختیاری): لغو سفارش

```
مل‌مل
سفارش #ORDER# لغو شد.
اگر مبلغی پرداخت کرده‌اید، طبق قوانین بانکی به حساب شما بازمی‌گردد.
```

پارامترها: `ORDER`. متن بازگشت وجه را با سیاست واقعی فروشگاه چک کن، چون قول ضمنی می‌دهد.

### ۳.۷ `order_refunded` (اختیاری): بازگشت وجه

```
مل‌مل
مبلغ #AMOUNT# تومان بابت سفارش #ORDER# به حساب شما بازگردانده شد.
```

پارامترها: `ORDER`، `AMOUNT`.

### ۳.۸ `back_in_stock` (اختیاری): «موجود شد»

```
مل‌مل
کالای #PRODUCT# که منتظرش بودید موجود شد.
مشاهده و خرید:
https://YOUR-DOMAIN/#LINK#
```

پارامترها:
- `PRODUCT`: عنوان کوتاه‌شده (حداکثر ۲۵ کاراکتر با `truncate_sms_value`).
- `LINK`: مسیر کوتاه اختصاصی (`short_link_param("p", product.pk)` به شکل `r/p3a7`، حدود ۸ کاراکتر) که به صفحه‌ی محصول redirect می‌شود. دامنه‌ی سایت (`YOUR-DOMAIN`) هنگام ثبت قالب در پنل sms.ir جایگزین می‌شود (مشابه قالب `otp`)، بنابراین مقدار ارسالی در پارامتر `#LINK#` همیشه زیر سقف ۲۵ کاراکتر API وریفای sms.ir (کد `114`) می‌ماند.

### ۳.۹ `admin_new_order` (اختیاری): اعلان به کارمندان

```
مدیریت مل‌مل
سفارش جدید #ORDER# به مبلغ #AMOUNT# تومان پرداخت شد.
```

پارامترها: `ORDER`، `AMOUNT`.

## ۴. قرارداد برای Claude Code

- یک adapter پیامک (`notifications`) با تابع `send_template(key, mobile, params: dict)`. `key` از جدول بخش ۲ است و شناسه از env خوانده می‌شود. **نبودن شناسه‌ی قالب خطای startup نیست:** ارسال انجام نمی‌شود، `SmsLog(status="skipped_no_template")` و یک warning ثبت می‌شود و جریان اصلی (سفارش، وضعیت) ادامه می‌یابد. تنها استثنا `otp`: اگر backend واقعی است و شناسه‌ی آن خالی است، درخواست کد با پیام «ارسال پیامک در حال حاضر ممکن نیست» رد می‌شود (و `check_launch` خطا می‌دهد). در توسعه `SMS_BACKEND=console`.
- نام پارامترها **دقیقاً** همان‌هایی است که در هر قالب نوشته شده. اضافه یا کم نکن.
- فرمت مقادیر: شماره‌ی سفارش به شکل ذخیره‌شده (`ML-…`)، مبلغ تومان با ویرگول هزارگان و ارقام لاتین، کد OTP ارقام لاتین. مقدار پارامتر نباید خط جدید داشته باشد.
- هر ارسال در `SmsLog` ثبت شود (بدون مقدار `CODE`).
- ارسال‌های غیر OTP **خارج از تراکنش دیتابیس** و بعد از `on_commit` انجام شود. شکست ارسال نباید تغییر وضعیت سفارش را برگرداند. **تلاش مجدد خودکار وجود ندارد** (P6، D-P6 §4): پیامک وضعیت یک‌بار در `on_commit` فرستاده می‌شود و اگر شکست خورد فقط در `SmsLog` و لاگ می‌ماند؛ اکشن ادمین «ارسال دوباره‌ی پیامک وضعیت فعلی» برای کارمند گذاشته شده است. برای «موجود شد» استثناست: اگر ارسال شکست بخورد `notified_at` پاک می‌شود و اجرای بعدی `send_back_in_stock` دوباره تلاش می‌کند.
- `back_in_stock` فقط در بازه‌ی ۰۸:۰۰ تا ۲۱:۰۰ به وقت تهران ارسال شود (پیامی که به تبلیغ نزدیک است)، خارج از آن به صبح بعد موکول شود. `[ASSUMPTION]`
- در حالت توسعه (`DEBUG` یا `SMS_BACKEND=console`) هیچ پیامکی واقعی نرود و متن در کنسول چاپ شود.
- قرارداد API وریفای (تطبیق‌داده‌شده با `docs/vendors/smsir/smsir-api.md`):
  - آدرس: `POST https://api.sms.ir/v1/send/verify`
  - هدرها: `X-API-KEY: <SMSIR_API_KEY>`، `Content-Type: application/json`، `Accept: application/json`
  - بدنه: `{"mobile": "09123456789", "templateId": 100000, "parameters": [{"name": "CODE", "value": "1234"}]}` (`templateId` عدد صحیح، `name` بدون `#`، هر `value` بدون خط جدید و حداکثر ۲۵ کاراکتر)
  - پاسخ موفق: HTTP `200` و `status == 1`؛ شناسه‌ی پیامک در `data.messageId` است. کدهای خطای مهم: `10/11/12` کلید یا IP نامعتبر، `20` محدودیت نرخ، `102` کمبود اعتبار، `104` موبایل نادرست، `113` قالب یافت نشد، `114` طول پارامتر بیش از ۲۵ کاراکتر، `116` نام پارامتر خالی، `119` نیاز به ارتقای پنل.

### سمت مرورگر (فاز P2)
- فیلد کد: `autocomplete="one-time-code"` و `inputmode="numeric"` (طبق راهنمای otp در اسکیل daisyui).
- اختیاری: `[ASSUMPTION]` Web OTP API (`navigator.credentials.get({ otp: { transport: ['sms'] } })`) برای خواندن خودکار کد در مرورگرهای پشتیبان. بعد از دریافت، فرم را خودکار تایید نکن؛ فقط فیلد را پر کن و کاربر دکمه را بزند.

- پارامتر `LINK` از طریق پیوند کوتاه بدون جدول `short_link_param("p", product.pk)` به صورت `r/p3a7` (حداکثر ۲۵ کاراکتر) ارسال می‌شود و برای مقادیر متنی مثل نام محصول تابع `truncate_sms_value` استفاده می‌شود.

## تغییرات
- ۰.۵ (P6) — یادداشت «بدون تلاش مجدد خودکار؛ اکشن ادمین» در بخش ۴ (پارامترها و شناسه‌ها بدون تغییر).
- ۰.۴ (اصلاحی P2-ب) — جایگزینی پیوند کوتاه بدون جدول (`short_link_param("p", product.pk)` به‌شکل `r/p3a7`) در بخش‌های ۳.۸ و ۴ و حذف ارجاع به مدل/جدول `ShortLink` (D32).
- ۰.۳ (اصلاح P2) — بازگرداندن `#LINK#` در `back_in_stock` از طریق پیوند کوتاه امن (`short_link_param`)، سقف ۲۵ کاراکتر و اعتبارسنجی پیش از ارسال، و پیش‌فرض `SMS_BACKEND=console`.
- ۰.۲ (P2) — تطبیق کامل با `docs/vendors/smsir/smsir-api.md`: ثبت آدرس، هدرها، بدنه و کدهای وضعیت متد Verify؛ حذف پارامتر `#LINK#` از قالب `back_in_stock` و اجباری شدن سقف ۲۵ کاراکتر روی مقادیر پارامترها (به‌دلیل خطای `114` در API).
